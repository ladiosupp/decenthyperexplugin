# HyperEx 2.1.2 handoff — 2026-10-31

回退 2.1.1 的插件侧「只读诊断」改造，恢复 2.1.0 行为。

## 1. 为什么回退

2.1.1 把 `calibration-status`（诊断页加载时调用）从「验证并修复 profile」改成只读返回缓存，同时加了 10 分钟修复冷却、2 秒启动延迟。真机反馈：

- 偶发第一次无法启动 controller，跑 HyperEx 曲线时插件没有介入控制；
- 按冲洗后出水完成，但冲洗状态一直不退出，计时继续，切换曲线无效；
- 休眠再唤醒后恢复。

判断是修复/arming 的触发被削弱导致 profile 未及时校验，得不偿失。**不是诊断页的问题，是插件 `calibration-status` 的行为变化**。

## 2. 这次怎么改

- `plugin.js` 直接回到 `v2.1.0` 的代码，仅版本号改为 2.1.2；`manifest.json` 同步。
- 一并撤掉 2.1.1 的 profile 列表合并与启动延迟——确定性优先。
- 2.1.0 及更早的功能（Canvas/SVG 开关、预设回读、STEP 4 折叠、图表抽稀、ABORT 卡）保持不变。

## 3. 验证

- `node --check` 通过；578/578（与 2.1.0 相同的测试集）。
- 与 `v2.1.0` 的 plugin.js 逐字节比较：除版本号外完全一致。

## 4. 教训 / 以后再做

- 「减少写 profile」这类优化会改变 arming 时机，不能只看 REST 数量；要么保持 2.1.0 的验证节奏，要么先在真机跑满一周。
- 若还想省那几次 `GET /profiles`，只能做**只读合并**（同一轮里复用一次列表），不得删除/推迟 `calibration-status` 的 verify/repair，也不得加冷却。
- Streamline 收藏消失的问题仍未根治，需皮肤侧在检测到同标题 profile 换 id 时 repoint。
